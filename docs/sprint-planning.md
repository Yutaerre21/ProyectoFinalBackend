# Sprint Planning — propuesta, no acta de reunión

El taller establece tres sprints de dos semanas. El documento no completa sus fechas; se acordarán con el docente y G7. No se registran reuniones ni compromisos de integrantes inexistentes.

| Sprint | Objetivo propuesto                              | Backlog candidato             |
| ------ | ----------------------------------------------- | ----------------------------- |
| 1      | Acceso seguro e inventario ubicable             | HU01–HU05 y base de HU17      |
| 2      | Detectar riesgos y presentar estado del archivo | HU06–HU12 y ampliación HU17   |
| 3      | Ejecutar intervenciones y entregar operación    | HU13–HU16, HU18 y cierre HU17 |

Antes de cada Planning: revisar capacidad real, dependencias, feedback G7 y estimaciones. Crear milestone y asociar Issues aprobados. Las tareas pueden dividirse entre integrantes, manteniendo aportes verificables de cada uno.

**Registro real pendiente por sprint:** fecha, asistentes, enlace Teams, objetivo aprobado, Issues comprometidos, capacidad, responsables y riesgos. Estos campos se diligencian con hechos después de la reunión; este archivo no se presenta como acta válida.
